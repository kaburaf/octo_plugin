# Octo Virtual Playlists MCP

MCP- и REST-сервис для создания приватных виртуальных плейлистов Octo из списка `Исполнитель — Название`. Уже локальные треки воспроизводятся из Navidrome, отсутствующие — через онлайн-источник Octo. Создание плейлиста не скачивает музыку в медиатеку.

Интеграция не использует YouTube Music API, cookies Google или `ytmusicapi`. Сам Octo может использовать YouTube для онлайн-воспроизведения.

## Что потребуется

- Docker Engine с Docker Compose v2 на компьютере или сервере, где будет работать сервис.
- Запущенный Octo с настроенным Navidrome. Нужны API `importText`, `getImports`, `getImport`, `importAction` и виртуальные импортированные плейлисты. Интеграция проверена с Octo `2026.10.22.1`.
- Логин и пароль пользователя Navidrome, которому должны принадлежать создаваемые списки.
- Python 3 на хосте для подготовки файла авторизации. Для самого сервиса Python уже включён в Docker-образ.
- Доступ к Docker Hub и PyPI для первой сборки.
- Для подключения через туннель — отдельно выданные OpenAI Secure MCP Tunnel ID и control-plane API key. Они не нужны при прямом подключении MCP-клиента по HTTP.

Octo устанавливается отдельно: [официальный проект](https://github.com/winters27/octo). Этот репозиторий запускает только интеграцию плейлистов и, при необходимости, клиент туннеля.

## Установка с нуля

Все команды запуска выполняйте на хосте Docker. Ниже используются примеры каталогов `/srv/octo-playlists/config` и `/srv/octo-playlists/tunnel`; можно выбрать другие, указав одинаковые пути в `.env` и командах подготовки.

### Шаг 1. Подготовьте Octo

1. Убедитесь, что через Octo можно войти под своей учётной записью Navidrome.
2. Настройте онлайн-воспроизведение в самом Octo и проверьте один отсутствующий в медиатеке трек.
3. Для определения уже локальных треков настройте доступ администратора Navidrome в **Music server** Octo.
4. Выключите **Keep what is played** и **Send played albums to Lidarr**. Иначе глобальные настройки Octo могут запускать загрузки при прослушивании независимо от этой интеграции.

Настройки виртуального плейлиста сервис выставляет сам: **Stream without downloading — включено**, **Get missing songs — выключено**, **Keep as playlist — выключено**.

### Шаг 2. Получите исходники и настройте `.env`

Клонируйте этот репозиторий или скопируйте его исходники на хост Docker. Перейдите в каталог проекта и создайте `.env` по `.env.example`:

```bash
cp .env.example .env
```

Отредактируйте значения, например:

```dotenv
HTTP_BIND=127.0.0.1
HTTP_PORT=8765
OCTO_DATA_DIR=/srv/octo-playlists/config
TUNNEL_CONFIG_DIR=/srv/octo-playlists/tunnel
```

`127.0.0.1` подходит для проверки на самом хосте и для подключения через туннель. Для прямого подключения с другого устройства укажите в `HTTP_BIND` LAN-адрес хоста Docker и используйте этот адрес в URL клиента.

Сервис не реализует отдельную авторизацию MCP/REST: его инструменты работают от сохранённого пользователя Navidrome. Порт API должен быть доступен только доверенным клиентам; публиковать его в интернет для работы туннеля не требуется.

### Шаг 3. Подключите интеграцию к сети Octo

В `compose.yml` используется внешняя Docker-сеть `arr`. Проверьте её наличие:

```bash
docker network inspect arr
```

Если сети нет, создайте её и подключите к ней контейнер Octo через его Compose-конфигурацию:

```bash
docker network create arr
```

Если Octo уже использует другую общую сеть, вместо создания новой укажите её имя в `networks.arr.name` файла `compose.yml`.

В секции `environment` сервиса `octo-playlists` проверьте:

```yaml
OCTO_URL: http://octo:8080
OCTO_PUBLIC_URL: http://octo.example.lan
```

- `OCTO_URL` — адрес, доступный **из контейнера интеграции**. `octo` здесь — сетевое имя контейнера Octo, `8080` — его внутренний порт. При другом имени или порте замените значение. `localhost` внутри контейнера означает саму интеграцию.
- `OCTO_PUBLIC_URL` — адрес панели Octo для пользователя; он возвращается в ответах как `dashboard_url`.

### Шаг 4. Создайте файл авторизации

Команда ниже интерактивно запросит логин и пароль Navidrome. Значения не окажутся в истории команд. В файл записывается Subsonic-токен `MD5(password + salt)`, а не пароль. Токен тоже является секретом: он позволяет обращаться к API от выбранного пользователя.

В примере используется путь из шага 2. Ввод логина также скрыт.

```bash
sudo python3 - <<'PY'
import getpass
import hashlib
import json
import os
from pathlib import Path
import secrets

folder = Path('/srv/octo-playlists/config')
folder.mkdir(parents=True, exist_ok=True)
folder.chmod(0o700)
os.chown(folder, 10001, 10001)
path = folder / 'octo-auth.json'
if path.exists():
    raise SystemExit('Файл уже существует; существующую авторизацию не перезаписываем.')

username = getpass.getpass('Логин Navidrome (ввод скрыт): ').strip()
password = getpass.getpass('Пароль Navidrome: ')
if not username or not password:
    raise SystemExit('Логин и пароль обязательны.')

salt = secrets.token_hex(16)
data = {
    'url': 'http://octo:8080',
    'username': username,
    'salt': salt,
    'token': hashlib.md5((password + salt).encode('utf-8')).hexdigest(),
}
fd = os.open(path, os.O_WRONLY | os.O_CREAT | os.O_EXCL, 0o600)
with os.fdopen(fd, 'w') as output:
    json.dump(data, output)
os.chown(path, 10001, 10001)
print('Файл авторизации создан; секреты не выводятся.')
PY
```

Если адрес Octo отличается, измените и поле `url` в примере. При запуске значение `OCTO_URL` из Compose имеет приоритет над этим полем.

Сервис работает с UID/GID `10001:10001`. Он должен иметь доступ к каталогу состояния и право создавать в нём файл блокировки; файл авторизации должен иметь права `0600` и принадлежать этому пользователю.

### Шаг 5. Подготовьте каталог туннеля

Даже если туннель пока не нужен, создайте пустой `tunnel.env`, чтобы Compose мог прочитать конфигурацию:

```bash
sudo install -d -m 0700 /srv/octo-playlists/tunnel
sudo touch /srv/octo-playlists/tunnel/tunnel.env
sudo chmod 0600 /srv/octo-playlists/tunnel/tunnel.env
```

Файл API-ключа потребуется только при включении профиля `tunnel`.

### Шаг 6. Соберите и запустите сервис

Из каталога проекта:

```bash
docker compose config --quiet
docker compose build octo-playlists
docker compose up -d octo-playlists
docker compose ps
```

Дождитесь состояния `healthy`, затем выполните проверки на хосте Docker:

```bash
curl --fail http://127.0.0.1:8765/health
curl --fail http://127.0.0.1:8765/auth/check
```

Если вы изменили адрес привязки или порт, подставьте их вместо `127.0.0.1:8765`.

Первый запрос проверяет только процесс. Второй действительно обращается к Octo/Navidrome. Ожидаемый ответ второго:

```json
{"authenticated": true, "backend": "octo"}
```

### Шаг 7. Подключите MCP-клиент

Для клиента с прямым доступом к сервису добавьте сервер типа **Streamable HTTP** с URL:

```text
http://АДРЕС_ХОСТА:8765/mcp
```

На самом хосте при привязке к loopback это `http://127.0.0.1:8765/mcp`. На другом устройстве используйте LAN-адрес из `HTTP_BIND`.

Для клиентов, поддерживающих portable `mcp.json`, пример конфигурации:

```json
{
  "$schema": "https://agent-plugins.org/schemas/1.0.0/mcp.schema.json",
  "mcpServers": {
    "octo-playlists": {
      "type": "streamable-http",
      "url": "http://127.0.0.1:8765/mcp"
    }
  }
}
```

В клиенте, который использует другой формат конфигурации MCP, укажите тот же URL через его настройки. Для первого теста вызовите `check_connection`: в результате должны быть `status: ok`, `backend: octo`, `authenticated: true` и `virtual_only: true`.

Техническое имя сервера, возвращаемое реализацией MCP, — `ytmusic-playlists` для совместимости старых подключений. Несмотря на имя, инструменты работают только с Octo.

### Шаг 8. При необходимости включите туннель

Для клиента без доступа к вашей LAN можно использовать OpenAI Secure MCP Tunnel. Сначала получите Tunnel ID и control-plane API key в используемом клиенте или его средствах управления туннелями. Это отдельные данные подключения; ключи Last.fm и пароль Navidrome вместо них не подходят.

Создайте файлы, не помещая ключ в командную строку:

```bash
sudo python3 - <<'PY'
import getpass
import os
from pathlib import Path

folder = Path('/srv/octo-playlists/tunnel')
folder.mkdir(parents=True, exist_ok=True)
folder.chmod(0o700)
key_path = folder / 'api-key'
if key_path.exists():
    raise SystemExit('Файл API-ключа уже существует; сначала проверьте старую настройку.')

tunnel_id = getpass.getpass('Tunnel ID (ввод скрыт): ').strip()
api_key = getpass.getpass('Control-plane API key: ').strip()
if not tunnel_id or not api_key or '\n' in tunnel_id or '\n' in api_key:
    raise SystemExit('Нужны непустые однострочные значения.')

fd = os.open(key_path, os.O_WRONLY | os.O_CREAT | os.O_EXCL, 0o600)
with os.fdopen(fd, 'w') as output:
    output.write(api_key + '\n')
env_path = folder / 'tunnel.env'
fd = os.open(env_path, os.O_WRONLY | os.O_CREAT | os.O_TRUNC, 0o600)
with os.fdopen(fd, 'w') as output:
    output.write('CONTROL_PLANE_TUNNEL_ID=' + tunnel_id + '\n')
env_path.chmod(0o600)
print('Настройки туннеля сохранены; секреты не выводятся.')
PY

docker compose --profile tunnel up -d
docker exec octo-playlists-tunnel wget -qO- http://127.0.0.1:8080/readyz
```

Ожидаемый результат проверки — `ready`. Подключите в клиенте именно тот туннель, ID которого сохранён в `tunnel.env`. Его внутренний MCP-адрес уже задан в Compose: `http://octo-playlists:8000/mcp`. После подключения проверьте обнаружение инструментов и вызов `check_connection` из клиента.

Один и тот же туннель не запускайте одновременно на двух хостах. Для проверки работающего клиента используйте `/readyz`: запуск `doctor` рядом с ним может конфликтовать с уже занятым служебным портом.

## Как пользоваться

### Создать плейлист из чата

Передайте название и список треков, например:

```text
Создай виртуальный плейлист «Вечер» в Octo без скачивания:
Burial — Archangel
Jamie xx — Loud Places
Son Lux — Easy
```

Клиент вызывает `create_playlist`. Сервис сохраняет список через Octo, включает режим онлайн-воспроизведения, читает его обратно и проверяет состав, порядок и настройки загрузки.

В ответе будут:

- `playlist_id` — ID импорта вида `file-...`; используйте его для чтения и удаления через эту интеграцию.
- `streaming_playlist_id` — ID виртуального списка для музыкальных клиентов.
- `virtual: true` и `download_missing: false`.
- `dashboard_url` — адрес панели Octo; найдите список в разделе **Import**. Это ссылка на панель, а не отдельная ссылка на конкретный плейлист.

В музыкальном клиенте сервером должен быть **Octo**, а не Navidrome напрямую. После обновления списка плейлистов появится созданная подборка. Отсутствующие треки будут воспроизводиться онлайн, уже локальные — из медиатеки.

Нажатие сердечка пользователем может запустить скачивание через настройки самого Octo. Для простого прослушивания ставить сердечко не нужно.

### Посмотреть и удалить списки

Доступны инструменты:

| Инструмент | Назначение |
| --- | --- |
| `check_connection` | Проверить авторизацию и получить виртуальные списки |
| `preview_tracks` | Проверить формат `Исполнитель — Название` без записи |
| `create_playlist` | Создать приватный виртуальный плейлист |
| `list_playlists` | Получить виртуальные плейлисты пользователя |
| `read_playlist` | Прочитать состав и настройки по `playlist_id` |
| `delete_playlist` | Удалить виртуальный импорт по `playlist_id` |

Примеры запросов из чата: «Покажи мои виртуальные плейлисты Octo», «Покажи состав плейлиста с ID …», «Удали виртуальный плейлист с ID …».

Удаление плейлиста не удаляет аудиофайлы из медиатеки. Сервис откажется менять импорт, у которого вручную включены скачивание отсутствующих треков или создание локального плейлиста Navidrome.

### Ограничения

- Плейлисты приватные и доступны только для чтения в музыкальном клиенте.
- Повторный запрос с тем же названием и тем же составом возвращает существующий список.
- Другой состав под тем же названием возвращает `409`: для новой подборки выберите другое имя. Автоматической перезаписи и отдельного инструмента редактирования нет.
- Порядок и повторы треков сохраняются. Проверка формата не подтверждает точное совпадение записи в онлайн-каталоге: источник для отсутствующего трека подбирает Octo при воспроизведении.
- Параметры `privacy_status` и `description` сохранены для совместимости: списки всегда `PRIVATE`, а описание API импорта Octo не сохраняет.
- После неоднозначной сетевой ошибки сначала прочитайте списки и убедитесь, что операция не завершилась. Не повторяйте запись вслепую.

## Работа через REST API

В примерах сервис доступен на самом хосте по адресу `http://127.0.0.1:8765`. При другом адресе замените его.

Создание:

```bash
curl --fail-with-body http://127.0.0.1:8765/api/playlists \
  -H 'Content-Type: application/json' \
  --data-binary @- <<'JSON'
{
  "name": "Вечер",
  "tracks": [
    {"artist": "Burial", "title": "Archangel"},
    {"artist": "Jamie xx", "title": "Loud Places"}
  ]
}
JSON
```

Список и чтение:

```bash
curl --fail http://127.0.0.1:8765/api/playlists
curl --fail http://127.0.0.1:8765/api/playlists/file-REPLACE_WITH_IMPORT_ID
```

Для удаления только виртуального списка подставьте его реальный `playlist_id`:

```bash
curl --fail -X DELETE \
  http://127.0.0.1:8765/api/playlists/file-REPLACE_WITH_IMPORT_ID
```

Полный список маршрутов:

| Метод и путь | Назначение |
| --- | --- |
| `GET /health` | Проверка процесса, без проверки авторизации |
| `GET /auth/check` | Проверка доступа к Octo/Navidrome |
| `POST /playlists/preview` | Проверка формата списка без изменений |
| `POST /api/playlists` или `/playlists` | Создание виртуального списка |
| `GET /api/playlists` | Список виртуальных плейлистов |
| `GET /api/playlists/{id}` | Чтение импорта |
| `DELETE /api/playlists/{id}` | Удаление виртуального импорта |

Для preview используйте тело с `name` и `tracks`, как при создании. В REST `tracks` также принимает строки вида `Исполнитель — Название`.

## Обновление и остановка

Для самостоятельного развёртывания из этого репозитория:

```bash
docker compose build octo-playlists
docker compose up -d octo-playlists
```

После обновления повторите `/auth/check` и `check_connection` в MCP-клиенте. Если добавились или изменились инструменты, обновите подключение в клиенте.

Остановить сервис и туннель:

```bash
docker compose --profile tunnel stop
```

Каталоги состояния, авторизации и туннеля сохраняются на хосте. При переносе на другой сервер скопируйте их с сохранением прав, настройте общую сеть с Octo и только затем переключите туннель. Если сервисы включены в общий Compose другого стека, управляйте ими из этого общего Compose вместо запуска второй установки с теми же именами контейнеров.

## Проверки и устранение проблем

Автоматические проверки после сборки:

```bash
docker run --rm \
  --mount "type=bind,src=$(pwd)/test_services.py,dst=/app/test_services.py,readonly" \
  --entrypoint python octo-playlists:3.0.0 \
  -m unittest -v test_services
```

Они проверяют отсутствие команд приобретения, порядок и повторы, повторное использование списка, отказ от перезаписи и удаление виртуального импорта. Это не заменяет проверку реального подключения и воспроизведения.

Для полной проверки создайте временный плейлист из одного локального и одного отсутствующего трека, прочитайте его через `read_playlist`, найдите его в музыкальном клиенте и запустите отсутствующий трек. Проверьте, что **Get missing songs** выключен и очередь загрузок Octo не пополнилась. После проверки удалите временный список.

| Симптом | Что проверить |
| --- | --- |
| `503`, авторизация не настроена | Существует ли `octo-auth.json`, верен ли путь и доступен ли файл UID 10001 |
| `401`, ошибка Octo `40` | Логин Navidrome и актуальность пароля, из которого получен токен; после смены пароля токен нужно сформировать заново |
| `502`, Octo недоступен | `OCTO_URL`, имя контейнера, внутренний порт и общую Docker-сеть |
| `Permission denied` для состояния | Владельца каталога состояния и файла авторизации: UID/GID 10001, каталог доступен для записи |
| Плейлист виден в Import, но отсутствует в плеере | Плеер должен подключаться к Octo; обновите список плейлистов |
| Трек не воспроизводится онлайн | Проверьте онлайн-источник и состояние самого Octo; preview этой интеграции не гарантирует наличие записи |
| `409` при создании | Под тем же названием уже есть другой состав; выберите новое имя |
| `409` при удалении | У импорта включены загрузки или локальный плейлист; сервис не меняет такие импорты |
| `/health` работает, инструменты недоступны | Отдельно `/auth/check`, транспорт MCP и, если используется, готовность туннеля |

Логи сервиса:

```bash
docker compose logs --tail=100 octo-playlists
```

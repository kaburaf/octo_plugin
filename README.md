# Octo Virtual Playlists

Интеграция создаёт приватные виртуальные плейлисты в Octo по списку `Исполнитель — Название`. Технический идентификатор MCP `ytmusic-playlists` сохранён для совместимости подключений; рабочие контейнеры называются `octo-playlists` и `octo-playlists-tunnel`. YouTube Music API, браузерная авторизация Google и `ytmusicapi` больше не используются.

Octo сам воспроизводит отсутствующие в медиатеке треки через свой онлайн-источник; уже локальные треки играют из Navidrome. Виртуальный список доступен только для чтения в музыкальном клиенте. Для изменения состава создайте список с другим названием; существующий список с другими треками не перезаписывается.

## Без скачивания

Сервис вызывает `importText`, затем включает только `importAction(action=stream)`. Он никогда не вызывает `fetch`, `songs`, `star`, создание локального плейлиста или команду скачивания. Перед публикацией проверяет `streamWithoutDownloading=true`, `getMissing=false`, `keepPlaylist=false`, состав и порядок треков, а затем читает список через `getPlaylist`.

В самом Octo оставьте выключенными **Keep what is played** и **Send played albums to Lidarr**. Нажатие сердечка пользователем остаётся отдельной командой Octo на скачивание: этот сервис её не выполняет. Смена глобальных настроек Octo или последующее включение Get missing songs вручную может изменить поведение прослушивания.

Названия принимаются как указал пользователь. Preview проверяет формат, но не обещает точное совпадение записи в онлайн-каталоге: подбор источника выполняет Octo при воспроизведении.

## Текущее размещение

Сервис и туннель работают в Arrstack (LXC 200, 192.168.1.150). Сервисы `octo-playlists` и `octo-playlists-tunnel` управляются общим `/opt/arrstack/docker-compose.yml`. Исходники на сервере: `/opt/arrstack/integrations/octo-playlists`.

API: `http://192.168.1.150:8765`; MCP: `http://192.168.1.150:8765/mcp`. Octo доступен сервису напрямую в общей Docker-сети `arr` по адресу `http://octo:8080`. Клиентский App использует прежний туннель, теперь запущенный на сервере. Локальные контейнеры остановлены, временный мост и его автозапуск удалены. Компьютер не требуется для работы сервиса.

Авторизация находится в `/opt/arrstack/config/octo-playlists/octo-auth.json`, принадлежит UID/GID 10001, права 0600. Поля: `url`, `username`, `token`, `salt`; используется Subsonic-токен вместо хранения пароля. Настройки туннеля и API-ключ находятся в закрытом `/opt/arrstack/config/octo-playlists-tunnel`. Эти файлы не входят в исходники, образ и архив плагина.

## Обновление на сервере

Обновите исходники в `/opt/arrstack/integrations/octo-playlists`, затем из `/opt/arrstack` выполните `docker compose build octo-playlists` и `docker compose up -d octo-playlists`. Туннель перезапускать для обновления Python-кода не требуется. Его готовность проверяется через `docker exec octo-playlists-tunnel wget -qO- http://127.0.0.1:8080/readyz`.

`compose.yml` в этом репозитории — вариант отдельного развёртывания на сервере с существующей сетью `arr`. Текущая установка использует общий Compose Arrstack: не запускайте второй экземпляр с теми же именами контейнеров и туннелем.

Настройки: `OCTO_AUTH_PATH` — закрытый JSON авторизации; `OCTO_URL` — внутренний адрес Octo; `OCTO_PUBLIC_URL` — адрес панели; `OCTO_LOCK_PATH` — общий файл блокировки операций (по умолчанию `/data/octo-playlists.lock`).

## MCP

Streamable HTTP: `http://192.168.1.150:8765/mcp`. Codex подключается к этому адресу, App — через существующий туннель. Технический идентификатор MCP `ytmusic-playlists` сохранён для совместимости, но все инструменты работают с Octo.

Инструменты: `check_connection`, `preview_tracks`, `create_playlist`, `list_playlists`, `read_playlist`, `delete_playlist`. ID импорта начинается с `file-`, отдельный `streaming_playlist_id` — идентификатор для музыкальных клиентов. `dashboard_url` ведёт в панель Octo: список находится в Import.

Параметры `privacy_status` и `description` оставлены для совместимости старых подключений. Octo импортирует списки только как PRIVATE; описание не сохраняется, потому что API импорта не поддерживает его.

Повторный запрос с тем же названием и тем же составом возвращает существующий список. Другой состав под тем же названием возвращает 409. Если связь оборвалась при записи, сначала прочитайте списки: не повторяйте запись вслепую. Удаление убирает только виртуальный импорт, не музыкальные файлы. Списки с включёнными загрузками или локальным плейлистом сервис менять отказывается.

## REST

- `GET /health`: процесс работает; не проверяет авторизацию.
- `GET /auth/check`: реальный запрос к Octo/Navidrome.
- `POST /playlists/preview`: проверка списка без изменений.
- `POST /api/playlists` (также `/playlists`): создание виртуального списка.
- `GET /api/playlists`: виртуальные списки.
- `GET /api/playlists/{id}`: состав и настройки.
- `DELETE /api/playlists/{id}`: удалить виртуальный импорт.

Тело создания: `{"name":"Вечер","tracks":[{"artist":"Burial","title":"Archangel"},{"artist":"Jamie xx","title":"Loud Places"}]}`. В REST также допускаются строки `Исполнитель — Название`.

Старый endpoint `/admin/auth` с cookies YouTube удалён.

## Проверки

`python -m unittest -v test_services` проверяет отсутствие команд приобретения, сохранение порядка/повторов, повторное использование, отказ от перезаписи и безопасное удаление. Runtime-проверка отдельно создаёт временный виртуальный список, читает его через API музыкального клиента, подтверждает отсутствие очереди загрузок и затем удаляет тестовый список.
